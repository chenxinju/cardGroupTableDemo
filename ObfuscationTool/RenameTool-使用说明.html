完成度说明

已可用：日常「单任务混淆 + 回滚」。
未做：一次勾选连跑多阶段流水线。多阶段请手动分步跑，或用 CLI JSON。

功能介绍

RenameTool 是 macOS 图形工具，用来批量改 iOS/macOS 工程里的类名（并同步改引用与 pbxproj）。

它根据你选的规则生成「旧名 → 新名」映射，写进源码，并把 mapping JSON 存到指定目录，方便以后回滚或复用。

仅换前缀

只改类名前缀，中间与后缀不动。适合统一品牌前缀、小范围改名。

全量随机

前缀 + 随机中间词 + 类型后缀。适合需要强混淆、降低可读性。

回滚

按某次混淆留下的 Mapping JSON，把类名改回去。多步混淆时按相反顺序回。

打开方式

用 Xcode 打开工程，选 scheme RenameTool，按 ⌘R 运行：

/Volumes/D/githubDemo/cardGroupTableDemo/ObfuscationTool/RenameTool.xcodeproj

类名怎么变

仅换前缀

QIFFooView → HRFooView（中间 Foo、后缀 View 不变）

全量随机

结构：前缀 + 随机中间词 + 类型后缀

例：VEH + FibronVocalx + ViewModel → VEHFibronVocalxViewModel

字段与选项说明

每个字段：作用 · 示例值 · 填这个的意思。

字段作用 / 示例
project_path 源码根目录（通常指到 …/Sources）。 例：…/MyApp/Sources — 工具从这里扫 Swift/ObjC 并改文件。
maps_dir
Mapping 输出目录		 混淆时写出 mapping JSON 的目录。 例：…/ObfuscationTool/maps — 跑完后这里会出现新的 *.json。
Mapping JSON
回滚 / 复用		 回滚或复用时读入的那份 json（不是 maps_dir）。 例：…/maps/rename_20261019.json — 指定「按这份映射改回去 / 复用」。
target_folder
目标子目录		 只混淆该子目录；可空 = 整个 project_path。回滚不用。 例：Features/Home — 只动 Home 下的类；空着 = 全 Sources。
pbxproj 可空。空则工具会猜 …/AppName.xcodeproj/project.pbxproj。 注意：不要填错成 Sources.xcodeproj。拿不准就留空。
任务预设 一键切换常见模式（见下节）。 例：选「① 仅换前缀」— 界面切到前缀相关输入，其它置灰。
旧前缀 / 新前缀 仅换前缀时填写；各项目不同，预设不替你填死。 例：旧 QIF、新 HR — 所有 QIF* 类变成 HR*。
回滚模式 勾选后进入回滚；无关输入会置灰。 例：勾上 → 主要填 project_path + Mapping JSON，再跑。
复用旧 mapping 不重新随机，按已有 Mapping JSON 的映射再应用一遍。 例：勾上并选上次的 json — 同一批旧名仍映射到同一批新名。
中间词库 / 词包 仅全量模式可用；仅换前缀 / 回滚时置灰。 例：选 Viven — 随机中间词从该词包抽；也可选自定义。
Python / 脚本路径 实际执行混淆逻辑的 Python 环境或脚本入口；一般保持默认即可。 例：机器上的 python3 或工程自带脚本路径 — 跑不通时先确认本机有可用 Python。
常见填法（速记）
混淆：project_path = Sources，maps_dir = 放 json 的目录，target_folder 按需，pbxproj 可空。
回滚：project_path = 同一 Sources，Mapping JSON = 那次写出的文件；不必填 target_folder。

任务预设

  • 自定义 — 自己勾选项、填字段。
  • ① 仅换前缀 — 自己填旧/新前缀（各项目不同，不写死）。
  • ② 全量随机中间词 — 自己填前后缀（常填成相同，表示前缀保留、只随机中间）。
  • ③ 同 ②，并自动展开词库面板 — 结果与 ② 相同，只是打开词库 UI。

② 与 ③ 混淆结果一样；③ 方便你边选词包边调。

中间词库

仅全量模式可用；仅换前缀 / 回滚时置灰。

词包：Viven / HeyLens / frezz / PebbleSeeQ / 自定义。

推荐操作流程

第一次混淆（新人按这个走）

  1. Xcode 打开 RenameTool.xcodeproj，scheme RenameTool，⌘R。
  2. project_path 指到要改的工程 …/Sources。
  3. maps_dir 选一个专门放 mapping 的目录（建议单独文件夹，别和源码混）。
  4. 需要只动一块代码时填 target_folder；否则留空。 pbxproj 不确定就留空。
  5. 任务预设选 ①（换前缀）或 ②/③（全量）。填好旧/新前缀，或前后缀 + 词包。
  6. 跑任务。看窗口下方日志；成功后到 maps_dir 确认新生成的 Mapping JSON，记好路径（回滚要用）。
  7. 回 Xcode 编译目标工程。若红字：关掉工程再开；不要手动作批量「重新添加」文件。

回滚（按相反顺序）

  1. 勾选回滚模式（无关项会置灰）。
  2. project_path 指到要恢复的那份 Sources。
  3. Mapping JSON 选对应阶段写出的那份 json（不是 maps_dir 本身）。
  4. 若曾多步混淆：后生成的 mapping 先回，再回更早的。
  5. 跑完后若 Xcode 仍红：关工程再开。工具应已改 pbxproj；仍红再查窗口下方日志。

回滚要点（再强调）

  • 回滚读的是 Mapping JSON 字段，不是 maps_dir。
  • target_folder 回滚时不用。
  • 多步必须逆序；顺序反了可能对不上名。

常见注意

  • 前缀因项目而异，预设不替你填具体前缀。
  • mapping JSON 保存在 maps_dir；回滚 / 复用靠 Mapping JSON 字段指向具体文件。
  • 日志与 Mapping 结果在窗口下方，可拉宽窗口查看。
  • 一次连跑多阶段流水线未做：多阶段请分步手动，或 CLI JSON。
